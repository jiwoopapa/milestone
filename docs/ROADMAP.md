# 개발 로드맵 — AI 기반 습관 & 루틴 관리 웹앱

> PRD 기반 단계별 개발 계획. 각 단계는 이전 단계의 결과물에 의존하므로 순서를 지켜야 한다.

---

## Phase 1. 프로젝트 골격 구축

**왜 이 순서인가:**
DB 스키마·인증·폴더 구조가 확정되지 않으면 이후 모든 기능이 중간에 뒤집힌다.
기반 없이 기능부터 만들면 구조를 나중에 통째로 바꿔야 하는 상황이 생긴다.

**작업 목록:**
- [ ] Supabase 프로젝트 생성 및 환경변수 설정 (`.env.local`)
- [ ] Supabase Auth 연동 (이메일/소셜 로그인)
- [ ] DB 스키마 설계 및 마이그레이션
  - `users`, `routines`, `routine_logs`, `goals`, `goal_logs`, `events` 테이블
- [ ] Next.js 미들웨어로 인증 보호 라우트 설정
- [ ] 앱 라우트 구조 확정
  - `app/(auth)/` — 로그인/회원가입
  - `app/(app)/dashboard/` — 메인 대시보드
  - `app/(app)/goals/` — 목표 트래커
  - `app/(app)/calendar/` — 가족 일정
  - `app/(app)/settings/` — 설정

**예상 소요:** 2~3일

**완료 기준:**
- Supabase 콘솔에서 테이블 확인 가능
- 로그인 후 `/dashboard`로 리디렉션, 미로그인 시 `/login`으로 차단
- 로컬에서 `npm run dev` 정상 실행

---

## Phase 2. 공통 모듈 개발

**왜 이 순서인가:**
모든 기능이 공통 레이아웃·훅·유틸에 의존한다.
공통 레이어 없이 기능부터 만들면 동일한 코드를 여러 곳에 반복 작성하게 되고,
나중에 한꺼번에 수정해야 하는 부채가 쌓인다.

**작업 목록:**
- [ ] 인증 관련 컴포넌트
  - `LoginForm`, `SignupForm` (React Hook Form + Zod)
- [ ] 앱 레이아웃 컴포넌트
  - `AppSidebar` (네비게이션), `AppHeader` (날짜/사용자 정보)
  - `DashboardLayout` (`app/(app)/layout.tsx`)
- [ ] Supabase 서버/클라이언트 분리 유틸 (`lib/supabase/server.ts`, `client.ts`)
- [ ] 공통 데이터 훅
  - `useUser()` — 현재 로그인 사용자
  - `useRoutines()` — 루틴 CRUD
  - `useGoals()` — 목표 CRUD
- [ ] 날짜 헬퍼 함수 (`lib/date.ts` — date-fns 기반)

**예상 소요:** 2~3일

**완료 기준:**
- 로그인/로그아웃 정상 동작
- `AppSidebar`에서 각 페이지로 이동 가능
- `useUser()` 훅으로 사용자 정보 반환 확인

## Phase 3. 핵심 기능 개발

**왜 이 순서인가:**
앱의 존재 이유인 기능들이다. 공통 모듈이 갖춰진 후 개발해야 중복 없이 빠르게 만들 수 있다.
루틴 대시보드 → Goal Tracker 순서로 개발해 MVP를 먼저 완성하고 지표 시각화를 붙인다.

### 3-1. 루틴 대시보드 (MVP)
- [ ] 루틴 CRUD UI (추가/수정/삭제 다이얼로그)
  - 시간대(아침·이동·저녁) 카테고리 선택
  - 반복 설정 (매일, 평일, 특정 요일)
- [ ] 시간대별 체크리스트 (`/dashboard`)
  - 오늘 날짜 기준 아침/이동/저녁 섹션 표시
  - 체크박스 완료 처리 → `routine_logs` 저장
  - 섹션별 완료율 (N/M) 표시
- [ ] 날짜 이동으로 과거 루틴 기록 조회

### 3-2. Goal Tracker
- [ ] 목표 CRUD UI (`/goals`)
  - 목표명, 단위(km, 권, 시간), 목표값, 기간 설정
- [ ] 달성 기록 수동 입력 (러닝 거리, 독서 권수 등)
- [ ] 진척도 시각화
  - 진행 바 (현재값 / 목표값)
  - 누적 그래프 (recharts 또는 shadcn chart)
- [ ] 월간/전체 통계 요약 카드

**예상 소요:** 7~9일

**완료 기준:**
- 루틴 등록 후 대시보드에 시간대별 표시, 체크 상태 새로고침 후 유지
- 목표 등록 후 진행 바 반영, 기록 추가 시 그래프 실시간 업데이트

## Phase 4. 추가 기능 개발

**왜 이 순서인가:**
핵심 가치를 검증한 후 부가 기능을 붙여야 방향이 흔들리지 않는다.
데이터가 쌓인 후에야 Markdown Export와 AI 코칭이 의미 있어진다.

### 4-1. Markdown Export (Obsidian 연동)
- [ ] 날짜 범위 선택 UI
- [ ] 완료된 루틴 + 목표 기록을 ACE 프레임워크 형식 MD로 변환
- [ ] 브라우저 다운로드 또는 클립보드 복사

### 4-2. 가족 이벤트 캘린더
- [ ] 월간 캘린더 뷰 (`/calendar`)
- [ ] 이벤트 CRUD (제목, 날짜, 카테고리: 산행/캠핑/기타)
- [ ] 루틴 완료 현황 캘린더에 오버레이

### 4-3. AI 코칭
- [ ] Claude API 연동 (`lib/claude.ts`)
- [ ] 루틴 미완료 패턴 분석 프롬프트 설계
- [ ] AI 코칭 UI (대시보드 사이드 패널 또는 별도 페이지)
  - 주간 루틴 달성률 요약 + 미완료 원인 분석 및 재조정 제안
- [ ] 스트리밍 응답 처리 (Vercel AI SDK)

**예상 소요:** 6~8일

**완료 기준:**
- MD 파일 다운로드 후 Obsidian에서 정상 렌더링
- 캘린더에서 이벤트 추가/수정/삭제 가능
- 루틴 데이터 기반 AI 분석 텍스트 스트리밍 렌더링

## Phase 5. 최적화 및 배포

**왜 이 순서인가:**
미완성 기능을 최적화하는 것은 낭비다. 전체 기능이 완성된 후에야 병목 지점을
정확히 측정하고 의미 있는 최적화를 할 수 있다.

**작업 목록:**
- [ ] Vercel 배포 설정 (환경변수 등록)
- [ ] Supabase RLS(Row Level Security) 정책 검토 및 강화
- [ ] React Query 또는 SWR 캐싱 전략 적용
- [ ] 이미지/폰트 최적화 (`next/image`, `next/font`)
- [ ] Lighthouse 성능 점수 90+ 달성
- [ ] E2E 핵심 플로우 테스트 (로그인 → 루틴 체크 → 목표 기록)
- [ ] 커스텀 도메인 연결 (선택)

**예상 소요:** 2~3일

**완료 기준:**
- Vercel 프로덕션 URL로 전체 기능 동작 확인
- Lighthouse Performance 90+, Accessibility 90+
- RLS 활성화 상태에서 타 사용자 데이터 접근 차단 확인
